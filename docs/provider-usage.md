# 사용량 플러그인 표시 제한

`provider-usage`의 상태바·툴팁·상세 패널·한도 알림에는 GPT와 Claude만 표시한다. 내부 제공자 ID는 GPT가 `openai-codex`, Claude가 `anthropic`이다. 표시명은 GPT·Claude로 맞춘다. 연결되지 않은 계정을 억지로 표시하거나 조회 실패를 사용량 0으로 바꾸지 않는다.

원본 v0.2.0의 눈 버튼은 상태바 표시만 조절한다. 상세 패널과 알림까지 제한하는 기본 설정은 확인되지 않아, 이 저장소의 표시 어댑터를 적용한다. 공식 플러그인의 기본 기능과 구분한다.

## 설치 AI가 수행할 작업

플러그인을 설치·활성화한 뒤 설치 요청 한 번으로 다음 단계까지 수행한다.

```sh
python3 scripts/configure_provider_usage.py
python3 scripts/configure_provider_usage.py --apply
```

첫 명령은 읽기 전용 미리보기다. 기본 홈은 `${HERMES_HOME:-$HOME/.hermes}`이며 `--home`으로 선택한 프로필을 지정할 수 있다. 도구는 해당 홈의 `plugins/provider-usage/desktop/plugin.js`와, 존재하면 `desktop-plugins/provider-usage/plugin.js`를 함께 확인한다. Desktop 복사본이 없으면 화면 적용 완료로 보고하지 않는다.

Desktop이 다른 홈에 플러그인 복사본을 보관하면 실제 위치를 확인해 `--desktop-home`을 명시한다. Desktop 복사본은 앱 수준으로 공유될 수 있으므로 다른 프로필에도 표시 제한이 적용되는지 범위를 확인한다. 다른 프로필의 파일을 자동 탐색해 수정하지 않는다.

원본은 선택한 홈의 `backups/provider-usage/`에 권한 600으로 보존한다. 같은 어댑터는 변경 없이 건너뛴다. 관리 구간이 바뀌었거나 원본의 예상 코드가 다르면 기존 파일을 보존하고 중단한다. 플러그인 업데이트로 어댑터가 사라질 수 있으므로 업데이트 뒤에는 미리보기와 표시 검증을 다시 수행한다. 복구할 때는 적용 대상과 일치하는 백업을 확인하고, 백업 이후의 사용자 변경을 덮어쓰지 않는다.

API 키·인증 파일·모델·OMH fallback은 수정하지 않는다. 이 어댑터는 표시와 알림만 제한한다. 원본 백엔드의 다른 제공자 조회 기능까지 비활성화하는 것은 아니다.

## 확인

- Node.js가 있는 환경에서 `python3 -m unittest discover -s tests -v`로 어댑터 검사와 JavaScript 필터 실행 테스트를 수행한다.
- 실제 Desktop에서 GPT·Claude만 상태바·툴팁·상세 패널에 표시되는지 확인한다. 눈 버튼은 두 제공자 중 상태바에 보일 항목을 고르는 용도로 유지한다.
- 수동 새로고침 뒤에도 표시 제한이 유지되는지 검사한다. 숨긴 제공자의 한도 알림도 발생하지 않아야 한다.
- 새로고침 주기·Used/Remaining 선택·기존 상태바 선택은 보존한다. 저장된 `barProviders`가 없거나 `null`이면 연결된 GPT·Claude 둘 다 상태바에 보인다. 명시한 빈 목록은 빈 상태바로 유지하고, 한 제공자만 고른 목록은 그 선택을 유지한다. 다른 제공자 ID는 표시만 숨기며 저장 목록에서 삭제하지 않는다. 이후 눈 버튼을 눌러도 숨긴 ID는 저장 목록에 남는다.

이전 어댑터의 저장 목록 필터링 구문은 완전한 관리 구간과 모든 예상 구문이 일치할 때만 보존형 구문으로 갱신한다. 부분 적용·사용자 변경·혼합 버전은 계속 거부한다. 앱이 변경 파일을 자동으로 읽지 않으면 지원하는 플러그인 재로딩을 사용하며, 실행 중인 세션을 종료하거나 전체 앱을 강제로 재시작하지 않는다.

전체 플러그인 DOM 검사는 설치된 원본과 Desktop 복사본을 임시 홈에 복사한 뒤, 실제 React·React Query·nanostores·jsdom으로 각각 마운트한다. 기본 표시·빈 선택·단일 선택·숨긴 ID 보존·주기와 값 모드·조회 실패·미연결·수동 새로고침·숨긴 제공자의 알림 차단을 검사한다. 필요한 의존성이 없으면 이 검사만 건너뛰며 새 패키지를 설치하지 않는다. 별도 의존성 위치는 `HERMES_DESKTOP_NODE_MODULES`로 지정한다. 통합 검사 통과는 실행 중인 Electron 화면이 새 코드를 읽었다는 증거가 아니므로 실제 화면 확인은 따로 수행한다.
