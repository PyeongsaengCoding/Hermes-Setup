# 전역 규칙

이 저장소가 설치하는 전역 규칙은 사용자 의도·정정 반영과 Aside 브라우저 직접 조작 기준이다.

## 원본과 적용 위치

- 배포 원본: [Aside 브라우저 규칙](../templates/aside-browser.md).
- 배포 원본: [사용자 의도·정정 반영 규칙](../templates/user-intent.md).
- 적용 파일: 선택한 Hermes 프로필의 `SOUL.md`.
- 기본 홈: `${HERMES_HOME:-$HOME/.hermes}`. 이름 있는 프로필은 해당 프로필 홈을 명시한다.

```sh
python3 scripts/install_global_rules.py
python3 scripts/install_global_rules.py --apply
```

다른 프로필을 선택했다면 두 명령 모두 `--home "$HOME/.hermes/profiles/<이름>"`을 붙인다. 실행 전에 실제 프로필을 확인하며 다른 프로필에 일괄 적용하지 않는다.

미리보기는 파일을 쓰지 않는다. 적용 시 기존 내용을 보존하고 각 규칙을 관리 마커 안에 한 번씩 추가한다. 같은 규칙이 마커 없이 이미 있어도 추가하지 않는다. 기존 관리 규칙이 다르거나 관리 구간이 수정·손상돼 있으면 파일을 쓰기 전에 중단하고 차이를 확인한다. 해당 도구는 기존 규칙을 자동 업데이트하거나 덮어쓰지 않는다.

이전에 설치한 보고서 규칙은 `legacy_report_policy: present_preserved`로 알리고 보존한다. 개인 문구나 마커 없는 규칙을 임의로 삭제하지 않는다. 현재 사용 중인 전역 규칙 정리는 내용을 확인하고 승인된 범위에서 별도로 수행한다.

## 사용자 의도·정정 반영

사용자 목적과 에이전트가 선택한 방법을 구별하고 초기 해석은 잠정적인 것으로 다룬다. 정정이나 반대 근거가 나오면 기존 해석·계획·위임을 재검토하고 잘못된 가정에 따른 작업을 수정하거나 중단한다. 제안을 사용자 확정 요구로 취급하지 않는다. 세부 방법은 목적 안에서 자율적으로 선택하되 목적·범위·승인 경계를 바꾸거나 결과에 중요한 모호함이 남으면 확인한다. 완료 전에는 시험 통과뿐 아니라 바로잡힌 의도에 맞는 결과인지 확인한다.

## 브라우저 프로필

모든 브라우저 페이지의 열기·조작·검증은 Hermes 모델이 Aside의 MCP `repl` 또는 `aside repl`로 직접 수행한다. Aside 자체 AI 에이전트와 `aside exec`, 자연어 작업 위임은 사용하지 않는다. 직접 조작 오류를 자체 에이전트 호출로 우회하지 않는다. Aside 프로필은 현재 프로젝트의 규칙이 지정한 것을 따른다. 프로젝트가 프로필을 지정하지 않았다면 계정 작업 전에 올바른 프로필을 확인한다. 연결 복구와 실제 호출 검사는 [브라우저 안내](browsers.md)에 따른다.

이전 Aside 관리 규칙이 설치된 프로필에서는 설치기가 차이를 감지해 중단한다. 기존 관리 구간을 새 원본과 대조하고 사용자 승인 후 해당 구간만 갱신한다. 다른 규칙은 보존하며 다른 프로필에 자동 적용하지 않는다.

## 확인

적용 후 정확한 대상 파일을 읽어 사용자 의도·Aside 규칙이 각각 한 번 있으며 기존 내용이 보존됐는지 확인한다. 이어서 선택한 프로필의 새 Hermes 세션에서 SOUL.md 로딩과 프로젝트가 지정한 Aside 프로필의 repl 직접 조작을 확인한다. 파일 설치 성공만으로 모델의 규칙 준수까지 확인했다고 보고하지 않는다.

Hermes 문맥 파일과 SOUL.md의 역할은 [공식 문서](https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files)를 따른다. 진행 중인 세션에 파일 변경이 즉시 주입된다고 가정하지 않는다.
